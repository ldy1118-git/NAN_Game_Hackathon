# SNAP GAMES

**▶ [지금 플레이하기](https://nan-game-hackathon.vercel.app/)** — 설치 없이 브라우저에서 바로.
헤드폰을 쓰고, 처음이라면 타이틀의 **타이밍 맞추기**를 한 번 돌리는 걸 권한다.

리듬천국(Rhythm Heaven)식 콜 앤 리스폰스 리듬 미니게임. TypeScript + Canvas 2D, 엔진·에셋 없음.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입체크 + dist/ 생성 (base './' 라 파일 열기로도 실행됨)
```

같이 개발한다면 [CONTRIBUTING.md](./CONTRIBUTING.md)의 브랜치·충돌 규칙을 먼저 읽자.

## 배포

Vercel 에 붙어 있다. `main` 에 머지되면 자동으로 배포되고, **PR 을 올리면 그 PR
전용 프리뷰 주소가 댓글로 달린다.** 셋이 각자 미니게임을 만드는 구조라 이게 제일
쓸모 있다 — 리뷰할 때 브랜치를 받아서 돌려볼 필요 없이 링크만 누르면 된다.

빌드 명령이 `npm run build`(= `tsc --noEmit && vite build`)라 **타입 에러가 있으면
배포가 막힌다.** 같은 검사를 `.github/workflows/ci.yml` 에서도 돌린다 — 배포 설정과
무관하게 저장소만으로 검증이 되도록.

설정은 `vercel.json` 에 있고 건드릴 일은 거의 없다. `base: './'` 로 빌드하므로
`dist/index.html` 을 그냥 파일로 열어도 돌아간다.

미니게임은 두 갈래다. 위 다섯은 **박자에 맞춰 누르는 리듬 게임**이고,

양쪽이 그대로 공유한다.

### 도전! CHALLENGE

목록 맨 위의 **도전! CHALLENGE** 는 미니게임들을 순서 없이 이어서 하는 모드다. 한 게임만
반복하면 그 게임의 손버릇만 늘지만, 여기서는 조작이 판마다 통째로 바뀌므로
(자리 찾기 → 연타 → 길게 누르기 → 판단) 머리가 전환을 따라가는지를 묻게 된다.

쉬움 5판 · 보통 7판 · 어려움은 **있는 게임 전부**. 판 사이에는 3초짜리 소개
카드가 들어간다 — 곧바로 이어 붙이면 무슨 게임이 시작됐는지 알아채는 데 첫
두어 개를 버리게 되고, 그건 실력이 아니라 사고다.

판마다 점수 체계가 다르므로(콤보·초·개수) 등급만 공통 화폐로 쓴다. 등급을 점수로
바꿔 합치면 "여러 판을 고르게 잘했나"가 한 숫자로 나온다.

### 난이도와 패턴

게임 하나가 **쉬움 / 보통 / 어려움**으로 나뉜다. 목록에서 고르면 난이도 카드
셋이 뜨고, **셋 다 처음부터 고를 수 있다** — 잠가 두면 이미 잘하는 사람이 쉬운 걸
억지로 한 판 하고 와야 하고, 어려운 게 어떤 건지 구경해 보는 재미도 사라진다.
대신 깬 난이도에 표시를 남겨 "다음엔 여기"가 눈에 보이게 한다. 기록도 난이도마다
따로 남는다.

**같은 난이도라도 판마다 패턴이 다르다.** 채보를 배열에 박아 두면 서너 판 만에
외워지고, 그때부터는 반응이 아니라 암기가 된다. 그래서 난이도는 규칙(어떤 간격이
얼마나 자주, 몇 개까지 연달아, 화음은 얼마나)만 정하고 실제 배치는 씨앗에서 매 판
새로 뽑는다. 씨앗은 씬이 만들어 넘기므로 게임 안에서는 `Math.random` 을 쓰지 않는다
— `draw()` 가 순수 함수라는 규칙이 그대로 유지된다.

### 시작 전 설명

난이도를 고르면 **설명 화면**이 먼저 뜬다. 무엇이 움직이는지(되풀이 그림),
무엇을 누르는지(키 배지), 무엇이 점수가 되는지(한 줄). 그림은 게임이 직접 그린다
(`preview()`) — 자기 화면을 이미 그릴 줄 아는 쪽이 축약본도 제일 잘 그린다.

미니게임은 두 갈래다. 위 다섯은 **박자에 맞춰 누르는 리듬 게임**이고,
아래 여섯은 **박자에 매이지 않는 자유형**이다. 타이틀 메뉴·기록·일시정지·음량은
양쪽이 그대로 공유한다.

조작은 기본적으로 스페이스(또는 화면 클릭) 하나.

| 키 | |
| --- | --- |
| `Space` | 치기 · 점프 · 선택 · 멈춘 상태에서 이어서 하기 |
| `↑` `↓` | 메뉴 이동 |
| `←` `→` | 난이도 고르기 · 자유형 게임의 좌우 이동 |

## "딱딱 맞는" 느낌을 만드는 세 가지

리듬게임에서 소리와 그림이 어긋나 보이는 원인은 거의 항상 아래 셋 중 하나다.

**1. 시간의 출처를 하나로 묶는다 — `src/core/Conductor.ts`**

`requestAnimationFrame`의 델타를 누적하면 프레임이 한 번 밀릴 때마다 오차가 영구히
쌓인다. 이 프로젝트에서 시간의 유일한 출처는 `AudioContext.currentTime`이고,
화면에 그려지는 모든 값은 매 프레임 거기서 새로 계산된다.

시간 축이 셋이라 헷갈리기 쉬운데:

- `ctx.currentTime` — 오디오를 예약할 때 쓰는 시각. 여기 예약한 소리는 실제로는
  `outputLatency`만큼 뒤에 스피커에서 난다.
- `audibleTime` = `ctx.currentTime - outputLatency` — 지금 귀에 들리고 있는 소리의 시각.
  **화면과 판정은 반드시 이 축을 쓴다.**
- `inputOffset` — 키보드·OS·모니터가 먹는 지연. 환경마다 20~80ms씩 다르고 이건
  판정 등급이 통째로 갈리는 크기라, 캘리브레이션으로 재서 판정에서 빼준다.

**2. 소리는 반드시 미리 예약한다 — `src/core/AudioEngine.ts`, `src/core/Runner.ts`**

"지금 재생"하는 API는 일부러 만들지 않았다. `Runner`가 180ms 앞까지의 이벤트를
`ctx` 시각으로 미리 예약해두므로, 프레임이 튀어도 소리는 샘플 단위로 정확히 난다.
소리는 mp3가 아니라 오실레이터·노이즈로 직접 합성한다 — 파일마다 다른 무음 구간이나
디코딩 지연 없이 예약한 시각에 정확히 울린다.

**3. 그림은 상태가 아니라 박의 함수로 그린다 — `src/minigames/*`**

각 미니게임의 `draw()`는 오직 `beat`만 보고 그림을 결정한다. 위치나 속도를 내부
상태로 들고 프레임마다 적분하면 한 번만 밀려도 영구히 어긋나지만, 함수로 그리면
언제나 다시 맞는다. 그래서 튕겨내기의 공은 프레임이 얼마나 튀든 정확히 정박에
라켓에 닿는다.

여기에 화면 전체가 정박에 1% 부풀고(`PlayScene`), 마디 첫 박에 배경이 한 번
밝아지고(`stage.ts`), 캐릭터가 타점 직전에 예비동작을 하는(`handOpen`) 연출이
얹힌다. 개별로는 사소하지만 이게 "딱딱 맞아 보인다"의 실체다.

## 루프가 멈췄다 돌아올 때

탭을 옮기면 `requestAnimationFrame` 은 멈추지만 `AudioContext.currentTime` 은 계속
흐른다. 아무 대비가 없으면 돌아온 순간 두 가지가 한꺼번에 터진다 — 스케줄러가
밀린 구간을 한 프레임에 따라잡으며 **과거 시각으로 수십 개의 소리를 예약**하고
(Web Audio 는 과거를 "즉시"로 처리한다), 그동안의 노트가 **전부 놓침으로 확정**된다.
8초만 자리를 비워도 소리 78개 중 76개가 과거 시각이었고 노트 7개가 날아갔다.

세 겹으로 막는다.

| 층 | 하는 일 |
| --- | --- |
| `AudioEngine.stale()` | 과거 시각 예약을 버린다. 모든 소리가 여기를 지나므로 새 미니게임이 생겨도 다시 뚫리지 않는다 |
| `App` 의 멈춤 감지 | 간격이 250ms를 넘으면 씬에 알린다. `visibilitychange` 는 탭 전환만 잡고 창 가림·절전·긴 GC는 못 잡아서, 간격 자체를 신호로 쓴다 |
| `Conductor.pause(rewindSec)` | 멈춘 걸 알아챈 시점에서 되감아 멈춘다. 플레이어가 실제로 있던 자리로 돌려놔야 재개 직후 몰살당하지 않는다 |

멈춤 감지의 간격은 `rAF` 가 주는 시각이 아니라 **오디오 클럭으로 잰다.** rAF 의
시각은 그 프레임의 vsync 시각이라 복귀 직후 한 번은 멈추기 전 값이 그대로 올 수
있고, 실제로 그 한 프레임이 새서 노트 7개가 놓침으로 확정되는 걸 확인했다.
시간의 출처를 오디오 클럭 하나로 묶는다는 원칙이 여기에도 그대로 적용된다.

게임 쪽에서 따로 할 일은 없다. `draw()` 가 `beat` 의 순수 함수이기만 하면
멈춰 있는 동안 `beat` 가 고정되므로 화면도 알아서 얼어붙는다.

## 캐릭터

여섯 명은 그림 파일이 아니라 **도형으로 그린다**(`minigames/cast.ts`).

처음에는 `images/` 의 원본을 스프라이트로 그대로 썼는데 금방 한계에 부딪혔다.
팔이 그림에 박혀 있어서 손뼉·줄 돌리기·라켓 스윙이 전부 어색했고, 눈을 감을 수
없었다. 원본에서 입만 도려내는 것도 안 됐다 — 이 그림체는 입이 코와 인중 선으로
이어져 있어서 자동으로 지우면 코까지 날아간다.

그래서 원본을 **참고만 하고** 부위를 나눠 다시 그린다. 머리 / 몸통 / 팔 둘 /
다리 / 눈 / 입이 각각 독립이라 전부 따로 움직인다. 색은 원본에서 뽑은 값이고
실루엣과 소품(네모 머리·양갈래·새싹·리본)도 원본을 따라간다.

캐릭터마다 다른 건 `SPEC` 한 곳에 모여 있다 — 머리 모양, 옷, 머리카락, 눈 크기,
기울기 정도. 새 캐릭터를 넣으려면 여기에 한 줄 추가하면 된다.

```ts
drawCharacter(g, {
  id: 'man1', x, y: GROUND_Y, h: 150,
  squash, hop, tilt,        // 몸
  blink, look,              // 눈
  sing, tongue,             // 입
  armL, armR,               // -1 위로 / 0 옆으로 / 1 앞으로 모음(손뼉)
});
```

팔은 어깨에서 손까지 직선 하나로 그린다. 관절을 접지 않아도 자세가 읽히는
그림체라, **값 하나로 늘어뜨림·만세·손뼉이 다 나온다.** 앞으로 모은 팔만 몸통
앞에 그려서 손이 가려지지 않게 한다.

`idleBlink(beat, seed)` 로 가끔 깜빡이게 할 수 있다. `beat` 의 순수 함수라
프레임이 튀어도 어긋나지 않고, `seed` 를 다르게 주면 여섯이 따로 깜빡인다.

## 자유형 미니게임 추가하기

반응속도·피하기·연타처럼 박자와 무관한 게임은 `FreeGame` 을 구현한다.
채보도 판정 창도 없고 **메서드 넷**이면 된다.

```ts
export class MyGame implements FreeGame {
  readonly id = 'mygame';
  readonly title = '내 게임';
  readonly hint = '한 줄 설명';
  readonly order = 90;
  readonly keys = ['Space'] as const;   // 브라우저 기본 동작을 막을 키
  readonly duration: number;            // 제한 시간(초). 0 이면 done 이 끝을 알린다
  // 설명 화면이 쓰는 두 가지
  readonly controls = [{ keys: ['Space'], label: '무엇을 하는 키인지' }];
  readonly scoring = '어떻게 점수가 되는지 한 줄';

  private p: Params;
  private rng: Rng;

  // 생성자가 (난이도, 씨앗) 을 받는다. 난이도로 조임새를 정하고,
  // 씨앗으로 이 판의 배치를 뽑는다. Math.random 은 쓰지 않는다.
  constructor(difficulty: Difficulty, seed: number) {
    this.p = PARAMS[difficulty];
    this.duration = this.p.duration;
    this.rng = makeRng(seed);
  }

  start(audio) { /* 상태 초기화 */ }
  update(dt, t, input, audio) {
    if (input.pressed('Space')) { /* 이번 프레임에 새로 눌림 */ }
    if (input.down('ArrowLeft')) { /* 누르고 있는 중 */ }
  }
  draw(g, t) { /* 자유롭게 */ }
  preview(g, t) { /* 설명 화면의 되풀이 그림. (0,0)~(PREVIEW_W, PREVIEW_H) */ }
  result() { return { score, rank, headline, rows }; }
}
```

**여기서는 상태를 프레임마다 굴려도 된다.** 리듬 쪽에서 그걸 금지하는 이유는
소리를 미리 예약해 두기 때문인데, 자유형은 예약할 채보가 없다. 소리는 그때그때
`audio` 로 내면 된다.

등록은 리듬 게임과 똑같이 **파일만 만들면 끝**이다. `index.ts` 가 두 계약을
모두 알아보고 갈래(`kind`)를 붙여 준다. `order` 사다리도 공유하므로 리듬 게임과
섞어서 순서를 매길 수 있다.

조작이 겹치지 않게 하자. 지금 다섯 개가 각각 **자리 찾기(두더지) · 이동과 점프(피하기) ·
연타(달리기) · 길게 누르기(풍선) · 판단(가위바위보)** 로 나뉜다.
같은 손놀림이 두 번 나오면 모음이 금방 지루해진다.

난이도는 **한 번에 한 가지만 조이자.** 속도·개수·판정 창을 동시에 올리면 왜
어려워졌는지 아무도 모른다. 그리고 쉬움에서는 조작 하나를 빼 두는 게 좋다 —
피하기의 쉬움에 굴러오는 것이 없는 이유가 그것이다.

난이도는 **사람 손 기준으로 맞추자.** 연타는 초당 7~9번이 한계고, 그 언저리에서
승부가 갈려야 "조금만 더"가 생긴다. 헤드리스 봇으로 검증할 때 봇 속도를
사람 속도로 낮춰서 재는 걸 잊지 말 것 — 초당 30번 두드리는 봇은 뭐든 이긴다.

## 미니게임 추가하기 (리듬)

`minigames/` 에 `MiniGame` 을 구현한 클래스를 export 하는 파일을 만들면 **끝이다.**
`index.ts` 가 폴더를 훑어 자동으로 등록하므로 목록에 손으로 적을 필요가 없다.
시간·판정·점수·오디오 예약은 전부 `Runner` 가 처리하므로, 게임 쪽은 채보와
그림·소리만 정하면 된다.

```ts
export class MyGame implements MiniGame {
  readonly id = 'mygame';
  readonly title = '내 게임';
  readonly hint = '한 줄 설명';
  readonly order = 50;   // 메뉴 순서. 작을수록 위. 안 적으면 맨 뒤로
  readonly bpm: number;
  readonly endBeat: number;
  readonly controls = [{ keys: ['Space'], label: '언제 누르는지' }];
  readonly scoring = '어떻게 점수가 되는지 한 줄';

  // 채보는 씨앗에서 만든다. 배열에 박아 두면 몇 판 만에 외워진다.
  // 간격 목록으로 이루어진 채보라면 beat.ts 의 makeTravelPhrases / layoutPhrases 를 쓴다.
  constructor(difficulty: Difficulty, seed: number) { /* ... */ }

  build(): BeatEvent[] {
    return [
      { beat: 4, kind: 'cue' },                    // 게임이 들려주는 신호
      { beat: 8, kind: 'hit' },                    // 한 번 친다
      { beat: 12, kind: 'hold', endBeat: 14 },     // 12박에 눌러 14박에 뗀다
    ];
  }

  groove(step, t, a) { basicGroove(step, t, a); }   // step = 8분음표 인덱스
  scheduleCue(ev, t, a) { a.clap(t); }
  playerSound(t, v, a) { v === 'miss' ? a.bad(t) : a.good(t); }
  draw(g, r) { /* r.beat 만 보고 그린다 */ }
}
```

필수는 위의 여섯 필드와 메서드 다섯 개뿐이고, 나머지는 필요할 때만 선언하는 **선택 필드**다.
전부 기본값이 있으므로 안 적으면 기존 동작 그대로다.

| 선택 필드 | 기본값 | 언제 쓰나 |
| --- | --- | --- |
| `order` | 100 | 메뉴 순서. 10, 20, 30 처럼 띄엄띄엄 |
| `acceptedKeys` | `Space` `ArrowUp` | 여러 키를 쓰는 게임. `hit` 의 `data.key` 로 노트별 키를 지정하면 `Runner` 가 키마다 따로 매칭한다 |
| `hitWindowMs` | `WINDOW_MS` | 판정 창을 넓히거나 좁힐 때 |
| `verdictY` | 176 | 판정 문구 높이. 화면 **위쪽**을 쓰는 게임은 기본 자리가 그림과 겹친다 |

화면 아래쪽에 자기 UI를 두는 게임은 박자 점(기본 y=490)과도 겹치니
`drawStage(g, beat, GROUND_Y, <다른 y>)` 로 점을 옮긴다.

`draw()`를 쓸 때 자주 필요한 것들은 `minigames/beat.ts`에 있다. 매번 다시 만들지 말자.

- `decay(beat, at, duration, power)` — 타점 직후 1에서 0으로 떨어지는 곡선. 스쿼시·스윙에 쓴다
- `windUp(beat, next, window)` — 다음 타점이 다가올수록 커지는 예비동작 양.
  동작이 "박자에 맞아 보이는" 건 대부분 이것 덕분이다
- `prevBeat` / `nextBeat` / `prevAndNext` — 이벤트 목록에서 직전·다음 타점 찾기

판정 창은 `core/types.ts`의 `WINDOW_MS`에 있다 (완벽 ±52ms, 좋음 ±112ms, 150ms 초과 시 놓침).
BPM이 바뀌어도 체감 난이도가 같도록 박이 아니라 ms로 정의했다.

**`hold` 노트**는 누른 시각과 뗀 시각을 모두 판정하고, **둘 중 나쁜 쪽이 최종 판정**이다.
대충 누르고 정확히 떼는 걸로는 완벽이 안 나온다. 누르는 동안 이어지는 소리가 필요하면
`holdStart` / `holdEnd` 를 구현한다 — 이 소리는 박자 신호가 아니라 입력 피드백이므로
예약이 아니라 즉시 재생해도 된다 (`AudioEngine.charge()` 참고).

## 브라우저에 저장하는 값

| 키 | 내용 |
| --- | --- |
| `nan-game.inputOffset` | 캘리브레이션으로 잰 입력 지연(초) |
| `nan-game.volume` | 음량 0~1 |
| `nan-game.muted` | 음소거 |
| `nan-game.records` | 미니게임별 최고 기록 (`core/records.ts`) |

### 기록

미니게임마다 **항목별로 따로** 최고를 남긴다 — 등급, 최고 콤보, 완벽 수.
한 판을 통째로 갈아끼우면 "등급은 낮았지만 콤보는 최고였던 판"의 값이 사라진다.

타이틀 메뉴 오른쪽 끝에 사다리로 보인다.

| 표시 | 뜻 |
| --- | --- |
| (없음) | 아직 안 해봄 |
| 숫자 | 해봤음 — 최고 콤보 |
| 완벽 | `superb` 등급을 낸 적 있음 |
| ★ | 모든 노트를 완벽으로 낸 적 있음 |

저장된 값은 그대로 믿지 않는다. 손으로 고쳤거나 옛 형식일 수 있으므로
읽을 때 항목마다 타입을 확인하고, 이상하면 "기록 없음"으로 떨어뜨린다.
JSON 이 깨져 있어도 게임은 그대로 돈다.

`inputOffset` 은 **키가 있느냐 없느냐로 "한 번이라도 측정했는지"를 판단**한다
(`App.hasCalibrated`). 값이 0 인 것과 측정한 적 없는 것은 다르다. 그래서 측정을
취소했을 때는 원래 값으로 되돌리기만 하고 **저장하지 않는다** — 되돌리는 것까지
저장하면 측정한 적 없는 사람이 완료로 기록돼 첫 실행 안내가 다시는 안 뜬다.

한 번도 측정하지 않았으면 타이틀 화면에 안내가 뜨고 해당 메뉴에 점이 찍힌다.
입력 지연은 환경마다 20~80ms 씩 다르고 판정 등급이 통째로 갈리는 크기인데,
메뉴 맨 아래 항목 하나로 두면 아무도 누르지 않는다.

시크릿 모드에서는 `localStorage` 가 접근만으로도 예외를 던지므로 전부
try/catch 로 감싸 두었다. 저장이 안 돼도 그 세션에서는 정상 동작한다.
